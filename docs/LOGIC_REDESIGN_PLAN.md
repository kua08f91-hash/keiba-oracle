# KEIBA ORACLE — 予測ロジック刷新 詳細設計書（Phase 0〜4）

- 対象リポジトリ: `kua08f91-hash/keiba-oracle`
- 文書ステータス: 設計フェーズ（コード未着手）
- 作成日: 2026-05-20
- 方針決定: フィボナッチ／カオス理論は採用しない（category error・予測力ゼロのため取り下げ済み）。
  「眠っているML資産の本番化 → 交互作用の獲得 → キャリブレーション＋EV駆動の馬券選択」を基本路線とする。

---

## 0. エグゼクティブサマリ

現行 v5 は「重み付き線形和」モデルであり、構造的に**交互作用（脚質×馬場×ペース等）を表現できない**。
さらに調査の結果、最適化済み重みが読み込まれず破棄されている実害バグが存在する。

本計画は5段階で刷新する：

| Phase | 目的 | 利益への寄与 | 主リスク |
|---|---|---|---|
| 0 | バグ修正・検証基盤整備 | 前提条件（確実） | なし |
| 1 | Learning-to-Rank モデル（交互作用の獲得） | 大 | 過学習 |
| 2 | ペース・アジェントシミュレータ | 中〜大 | 検証困難・自由度過多 |
| 3 | キャリブレーション＋EV駆動の馬券選択 | **最大（利益直結）** | 中 |
| 4 | LLM最終判断レイヤー | 小〜中 | 再現性・バックテスト困難 |

各 Phase の末尾に **Go/No-Go ゲート**を設け、walk-forward 検証で改善が確認できない場合は次へ進まない。

### 現実的な期待値の明示（重要）

JRA の控除率は約25%。市場（オッズ）はそれなりに効率的であり、**控除率25%を継続的に上回るのは極めて難しい**。
本計画の現実的なゴールは「保証された利益」ではなく、
**(a) 損失の最小化、(b) 特定ニッチ（中穴・特定条件）での +EV の発見、(c) 意思決定の透明化と再現性**である。
この前提を共有しないまま「必勝モデル」を期待すると、過学習を誘発し必ず失敗する。

## 2. 設計原則（全 Phase 共通）

1. **リーク厳禁**：予測時点（発走7〜10分前の凍結時刻）で入手可能な情報のみ使用する。
   特にオッズは「凍結時オッズ」を使い、確定オッズ・結果由来の値を特徴量に混入させない。
2. **walk-forward 検証のみを信じる**：時系列で過去のみ学習・未来でテスト。ランダムCVは禁止（同日・近接レースの情報漏洩のため）。
3. **市場ベースラインを超えること**：「1番人気を買い続ける」「オッズ順」のベースラインを上回らない改善は採用しない。
4. **再現性**：固定シード、`temperature=0`（LLM）、凍結後不変。発走前凍結ルールは維持。
5. **段階的 Go/No-Go**：各 Phase は前 Phase の検証が通って初めて着手する。
6. **後方互換**：v5 は fallback／アンサンブル要員として残す。新モデルが壊れても予測が止まらないこと。
7. **過学習の可視化**：すべての評価で train/test ギャップを併記する。

## 4. 検証フレームワーク（Phase 0 で構築・全 Phase で使用）

### 4.1 walk-forward 分割

```
[学習 2023-01〜2024-12] → [テスト 2025-01]
[学習 2023-01〜2025-01] → [テスト 2025-02]
... 1ヶ月ずつローリング ...
```

- ハイパーパラメータ調整は学習区間内の検証フォールドのみで行う。テスト区間は最後まで触らない。
- 直近月を重視（時系列ドリフト対策、CLAUDE.md の知見を継承）。

### 4.2 評価指標

**予測精度（モデルの良し悪し）**

| 指標 | 意味 | 目標 |
|---|---|---|
| 勝者の負の対数尤度（NLL）/ log-loss | 確率予測の鋭さ | v5 と市場ベースラインを下回る（小さいほど良い） |
| Top-1 的中率 | 1着馬を当てた率 | 市場（1番人気≒25%）と比較 |
| Top-3 的中率 | 複勝圏予測 | 同上 |
| Brier スコア | 確率の二乗誤差 | 小さいほど良い |
| **ECE（期待キャリブレーション誤差）** | 「30%予測の馬が実際30%勝つか」 | Phase 3 で最小化 |
| Spearman 順位相関 | 順位予測の整合 | 参考 |

**馬券成績（最終的な利益）**

| 指標 | 意味 |
|---|---|
| ROI | 払戻 ÷ 投資 |
| 的中率 | 券種別 |
| 最大ドローダウン | 連敗時の最大資金減少 |
| 分散・標準偏差 | 成績のブレ |
| 月別・券種別 ROI | ニッチの発見 |

### 4.3 ベースライン（これを超えなければ採用しない）

1. **市場ベースライン**：オッズ順＝市場の予測。これがモデルが超えるべき本丸。
2. **現行 v5**：刷新前の自分。
3. **単純人気買い**：1番人気を機械的に買い続ける ROI。

### 4.4 過学習ガードレール

- 全評価で train/test ギャップを併記。ギャップ過大なら採用却下。
- テストセットは凍結。複数回テストして良い結果を選ぶ行為（test set peeking）を禁止。
- ハイパーパラメータ・特徴量選択の全判断を記録（実験ログ）。

## 6. Phase 1 — Learning-to-Rank モデル（中核）

### 6.1 目的

線形モデルの根本欠陥（交互作用を表現できない）を解消する。
決定木ベースのモデルは「脚質×馬場×ペース」「距離×血統」「斤量増×休み明け」等の交互作用を**自動学習**する。

### 6.2 モデル選定

- **本命：LightGBM**（または XGBoost）。
- **学習方式：conditional logit / listwise（推奨）**
  - 各馬について GBDT がスコアを出力 → レース単位で softmax → 実際の勝ち馬の負の対数尤度を最小化（Plackett-Luce / 条件付きロジット）。
  - 利点：**キャリブレーション済みの勝率が直接得られる**（馬券に直結）。「1レースに勝者は1頭」という制約を尊重。
- 代替：`lambdarank`（ランキング目的）。ただし確率が直接出ないため Phase 3 のキャリブレーションが必須になる。
- 現行 softmax(temp=9.5) は実は「非公式な条件付きロジット」。本 Phase はそれを**正式に最尤推定で学習する**もの。

### 6.3 特徴量設計

既存45特徴量をベースに、以下を追加する。**交互作用は木が自動で学習する**が、強力な相対特徴量は明示的に作る。

| カテゴリ | 新規特徴量 | 根拠 |
|---|---|---|
| **相対特徴量（最重要）** | フィールド内での順位：スピード指数ランク・オッズランク・斤量ランク・馬体重ランク、最上位馬との差 | 競馬では「絶対値」より「同レース内の相対位置」が強い予測子 |
| **ペア相性** | 騎手×馬の過去成績、騎手×調教師、騎手×コース、馬×コース、馬×距離帯、馬×馬場 | 「馬と騎手のペア相性」のユーザー要望に対応。スパースな組は埋め込み or 平滑化 |
| **ペース文脈** | フィールドの先行馬比率（`calc_pace_predict` を流用）、その馬の脚質×予測ペースの相互作用 | 差し馬はハイペース時のみ有利 — 交互作用の典型 |
| **季節・天候** | 月・季節、天候カテゴリ、馬の季節別成績 | 安価。効果は小さいが取りこぼし防止 |
| **ローテーション** | 休養日数、直近90/180日の出走数、クラス昇降、距離変更幅、芝↔ダ替わり | 「直近の休み」のユーザー要望に対応 |
| **相手構成** | 同型脚質頭数、強敵（高スピード指数馬）の有無、フィールドの実力分散 | 「組み合わせパターン」のユーザー要望に対応 |

**「馬 vs 馬の直接対戦」について**：同一の2頭が過去に対戦する回数は少なすぎ、統計的に信頼できない。
よって**直接対戦履歴ではなく「脚質マッチアップ（自分の脚質 × 相手の脚質構成）」で表現する**。これが統計的に正しい翻訳。

### 6.4 出力

- 各馬の **キャリブレーション前**勝率 P(win)。
- 上位3着確率（P(top2), P(top3)）は、勝率から Plackett-Luce 展開 or モンテカルロで導出。

### 6.5 学習規律

- walk-forward のみ。ハイパーパラメータは学習区間内検証で決定。
- early stopping、`max_depth` 抑制、`min_child_samples` 大きめ、`feature_fraction` 等で正則化。
- 特徴量重要度を毎回確認し、リーク疑い（不自然に重要な変数）を検出。
- v5 とのアンサンブル（加重平均）も検証対象に含める。

### 6.6 成果物

- `predictor/ltr_model.py`（学習・推論）
- 学習パイプライン（`train_ltr.py`）
- walk-forward 評価レポート

### 6.7 Go/No-Go ゲート

- walk-forward の log-loss / Top-3 が **v5 と市場ベースラインの両方を有意に上回る**。
- train/test ギャップが許容範囲（過学習していない）。
- → 満たさなければ特徴量・正則化を見直し。それでも超えないなら Phase 1 で計画を一旦停止し、データ拡充に戻る。

## 7. Phase 2 — ペース・アジェントシミュレータ（実験的）

### 7.1 目的

ユーザーの「シミュレーション」案の**正しい実装形**。
「カオス理論」が誤りである一方、その背後にある直感（僅かな差・展開が結果を一変させる）は正しい。
それを表現する適切な手法が**アジェントベースのレースシミュレーション**である。

### 7.2 設計

- 各馬を「エージェント」とし、以下のパラメータを持たせる：
  - 先行力（早い段階で前に行く力）
  - 持続力／スタミナ
  - 末脚（加速力・上がり性能）
  - 好む脚質、枠順（ゲート）
- レースをハロン単位で進行シミュレート：位置取り・スタミナ消耗を逐次計算。
- **ペースは創発する**：逃げ馬が複数いれば前半が速くなり、共倒れする — 交互作用が自然に発生。
- 各馬パラメータは過去走（区間タイム・上がり3F・通過順・脚質）から推定。
- N回シミュレート → 着順分布 → 勝率・連対率・複勝率。
- **敏感依存性の扱い**：各シミュレーションに確率的な揺らぎ（出遅れ・不利・展開差）を加え、多数回試行で分布を得る。これが「カオス」の直感の数学的に正しい実装。

### 7.3 統合方法

- 推奨：シミュレータの出力（勝率・展開有利度）を **Phase 1 モデルの特徴量として投入**する。
  → GBDT が「シミュレータをどれだけ信頼するか」を学習する。
- 代替：アンサンブル要員として GBDT 確率とブレンド。

### 7.4 リスクと位置づけ

- **自由パラメータが多く、過学習・検証困難リスクが最大**。だから Phase 1 ではなく Phase 2。
- シミュレータのパラメータ較正は、モデル学習とは別のデータ分割で行う。
- 区間タイムデータが取得できない場合、簡略版（脚質＋上がり3F＋通過順のみ）で実装。

### 7.5 Go/No-Go ゲート

- シミュレータ特徴量を加えた Phase 1 モデルが、加えない版より walk-forward log-loss を改善する。
- **改善しなければ Phase 2 は不採用**（実装は残すが本番投入しない）。これは「面白いが効かない」を正直に切る判断点。

## 8. Phase 3 — キャリブレーション＋EV駆動の馬券選択（利益直結・最重要）

### 8.1 目的

**どれだけ良いモデルでも、控除率25%に対して +EV の馬券だけを買わなければ利益は出ない。**
ここが ROI の本丸。現行 `optimize_bets()` は自分の EV を選別に使っていない（P-3）。

### 8.2 キャリブレーション

- モデルの生勝率を **isotonic regression** または **温度スケーリング**で補正。検証フォールドで学習。
- 信頼性ダイアグラム・ECE で「予測30%の馬が実際30%勝つ」ことを検証。
- キャリブレーションが不十分なまま EV 計算・Kelly を行うと破産するため、本 Phase の前提条件。

### 8.3 券種別確率の導出

- キャリブレーション済み勝率から、馬連・ワイド・3連系の的中確率を Plackett-Luce or モンテカルロ（既存 `monte_carlo_finish` 流用）で算出。
- 組合せ過大評価の補正（現行 `HITPROB_DEFLATION` の考え方）はデータで再較正。

### 8.4 EV駆動の馬券選択

```
各候補馬券について：
  EV = P(的中) × オッズ − 1     ← オッズは凍結時のリアルオッズ
  EV > 閾値（> 0、推定誤差マージン込み）の馬券のみ採用
  → EV順に選出、券種分散・1レース上限点数・リスク上限を制約として付与
```

- 現行の「オッズ帯×AI絡み×高オッズ順」を **EVランク選択**に置換。
- 推定オッズの馬券は採用しない（リアルオッズ必須）方針は維持。

### 8.5 ステーキング（賭け金配分）

- 初期：**フラットベット**（均等賭け）。キャリブレーションが実証されるまで Kelly は使わない。
- 実証後：**フラクショナル Kelly（1/4 Kelly 等）**へ移行。
- バンクロール管理：1レース最大エクスポージャ上限、連敗時の縮小ルール。

### 8.6 検証

- 馬券選択ロジックは**モデル確率を固定**して単独でバックテスト（選択ポリシーの ROI を分離評価）。
- 月別・券種別 ROI を見て、+EV のニッチ（中穴・特定条件）を特定。

### 8.7 Go/No-Go ゲート

- walk-forward で **市場ベースラインを上回る ROI**、または「損失を有意に圧縮」。
- 最大ドローダウンが許容範囲。
- ECE が十分小さい。

---

## 9. Phase 4 — LLM最終判断レイヤー（補助・最低優先）

### 9.1 目的

定量モデルが扱えない**定性情報**（除外馬・パドック気配・調教師コメント・当日の馬場バイアス・天候急変・ニュース）を取り込み、最終補正を行う。

### 9.2 設計

- **2段構成のステージB**：
  - 入力：Phase 1〜3 の構造化出力（各馬の名前・キャリブレーション済み確率・主要ファクター・EV馬券）＋定性情報。
  - タスク：**制約付き補正**。LLM は確率を ±X% 以内でのみ調整可能。必ず根拠テキストを出力。
  - 簡易版：LLM は確率計算をせず「異常検知・買い目の拒否（veto）」だけ行う。
- **LLM を確率エンジンにしない**：LLM はキャリブレーション不良かつ非再現的。確率の本体は Phase 1〜3 が担う。

### 9.3 再現性・コスト

- `temperature=0`、プロンプト＋応答をログ保存、発走前に凍結。
- 1レース1回（凍結時）のみ実行。固定指示部は prompt caching。

### 9.4 リスクと位置づけ

- **バックテストが困難**：過去の定性情報（パドック気配等）を遡って揃えるのは難しい。
- よって主にライブ運用での A/B 評価になる：LLM レイヤー有り／無しの ROI を継続比較。
- **改善が確認できなければ撤去**。Phase 4 は最低優先で、無理に入れない。

### 9.5 Go/No-Go ゲート

- ライブ A/B で LLM レイヤーが ROI を改善、または明確な誤り（危険な買い目）を一定数 veto できている。

## 10. リスク登録簿

| リスク | 深刻度 | 対策 |
|---|---|---|
| 過学習（CLAUDE.md に3回の失敗記録あり） | 高 | walk-forward 厳守、train/test ギャップ常時監視、テストセット凍結、Go/No-Go ゲート |
| データ不足（現状約1,200レース） | 高 | Phase 0 で3〜5年へ拡充。不足時は Phase 1 を保留 |
| データリーク（確定オッズ・結果の混入） | 高 | Phase 0-G でパイプライン全項目を監査 |
| 市場効率性（控除率25%の壁） | 高 | 期待値を正直に設定。「必勝」を目標にしない。ニッチ探索に徹する |
| Phase 2 の自由度過多 | 中 | 別データで較正、Go/No-Go で容赦なく不採用判断 |
| LLM の非再現性・コスト | 中 | temperature=0、凍結、1レース1回、A/B で撤去判断 |
| 区間タイムデータ取得不可 | 中 | Phase 2 を簡略版にフォールバック |
| スコープ肥大 | 中 | Phase ゲートで「効かないものは切る」を徹底 |

## 11. 撤退基準（全 Phase 共通）

以下のいずれかに該当したら、その Phase を**不採用**とし前 Phase の状態に戻す：

1. walk-forward でベースライン（市場 or v5）を超えられない。
2. train/test ギャップが過大（過学習が制御できない）。
3. 改善幅が運用・保守コストに見合わない。

**「実装したから使う」は禁止。** 効かないものを切る判断を各ゲートで明示的に行う。

## 12. 推奨実行順序とスコープ

```
Phase 0（基盤・バグ修正・データ）          ← 必須・最初
   ↓ ゲート通過
Phase 1（Learning-to-Rank）               ← 中核・最重要
   ↓ ゲート通過
Phase 3（キャリブレーション＋EV馬券選択）   ← 利益直結。Phase 2 より先でよい
   ↓ ゲート通過
Phase 2（ペースシミュレータ）              ← 実験的。Phase 1 の特徴量強化として後付け
   ↓ ゲート通過
Phase 4（LLM最終判断）                    ← 補助・最低優先
```

注：**Phase 3 を Phase 2 より先に行う**ことを推奨。利益への寄与が Phase 3 の方が確実かつ大きいため。
Phase 2 は「Phase 1 モデルの特徴量を1つ増やす」位置づけで、後からでも統合できる。

## 付録A. 用語整理（採用しない概念の明示）

| 概念 | 競馬予測での評価 | 理由 |
|---|---|---|
| フィボナッチ数列（予測ロジックとして） | **不採用** | 数秘術。予測力ゼロ |
| フィボナッチ（賭け金progression） | **不採用** | マーチンゲール系。期待値を改善せず破産確率を上げる |
| カオス理論 | **不採用** | 競馬は決定論的力学系でなく確率系。カテゴリ変数に適用対象が存在しない（category error） |
| モンテカルロ法 | **採用済み・継続** | 確率系の正しいシミュレーション手法。既に使用中 |
| アジェントベースシミュレーション | **Phase 2 で採用検討** | 「シミュレーション」案の正しい実装形 |
| 条件付きロジット / Learning-to-Rank | **Phase 1 で採用** | 「1レース1勝者」を尊重する標準的かつ強力な手法 |
| 勾配ブースティング木（LightGBM等） | **Phase 1 で採用** | 交互作用を自動学習。「組み合わせパターン」要望への正答 |
| キャリブレーション（isotonic等） | **Phase 3 で採用** | 利益を出すための必須前処理 |
